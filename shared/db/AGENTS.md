# AGENTS.md — `db` package

Drizzle ORM schemas and DB helpers. Read the root `AGENTS.md` first. This package is consumed via package-name subpath exports (`db`, `db/core`, `db/cache`, `db/wae`, `db/schemas/*`), which resolve to `./dist` — **rebuild (`npm -w db run build`) after edits** or consumers see stale types.

## Three storage tiers

The platform spreads data across three Cloudflare stores, each with its own Drizzle driver:

1. **Root D1** (`db/schemas/root`) — global lookup: tenants, users, API-key→tenant mapping, auth sessions. Accessed as `r_db` (`drizzle-orm/d1`).
2. **Durable Object SQLite** (`db/schemas/tenant/main`, `db/schemas/tenant/logs`, `db/schemas/user/main`) — per-tenant / per-user isolated DBs living inside Durable Objects. Accessed as `t_db` / user DB via `drizzleD0` from `db/core`. DOs are **jurisdiction-aware** (e.g. an `eu` jurisdiction) for data residency.
3. **Analytics Engine** (`db/schemas/wae`) — write-heavy operation metadata/logging. Accessed as `a_db` via `drizzleAE` from `db/wae`.

`db/cache` provides `SQLCache` (query caching with `all`/`explicit` strategies + TTL); `db/core` provides `DebugLogWriter`, `StaticDatabase` (DB name constants), and `drizzleD0`.

## Blob columns — the `unhex` rule

Primary keys and hashes are stored as **binary UUIDs / digests** (`blob({ mode: 'buffer' })`). Drizzle on D1/DO SQLite **cannot accept raw `Buffer`** in `.values()`, `.set()`, or `eq()`. Always convert a hex string at the DB level with `sql\`unhex(${hexString})\``:

```ts
import { eq, sql } from 'drizzle-orm/sql';

db.insert(table).values({ id: sql`unhex(${uuidHex})`, hash: sql`unhex(${digest.digest('hex')})` });
db.update(table)
	.set({ key_hash: sql`unhex(${newHashHex})` })
	.where(eq(table.id, sql`unhex(${idHex})`));
db.select()
	.from(table)
	.where(eq(table.id, sql`unhex(${idHex})`));
```

Read blobs back with `.toString('hex' | 'base64' | 'base64url')`. Many rows are mapped into a `BufferExport` shape (`{ buffer, hex, base64, base64url }`) after selection.

## Schema conventions

- Binary UUID PK: `t.blob({ mode: 'buffer' }).primaryKey().notNull()`. Derive hyphenated UUID strings in code with `hexToUuid` from `helpers` — there's no generated `*_utf8` column for this.
- Timestamps: stored as `integer`, not text. Drizzle's `mode` designates the epoch unit — e.g. `t.integer({ mode: 'timestamp_ms' })` for milliseconds. Check the column's `mode` to know which unit it holds before doing arithmetic on it.
- Prefer inferred model types (`table.$inferSelect` / `$inferInsert`) and derive view/input types with `Pick<>`/`Omit<>` rather than hand-written interfaces.
- Prefer `select().from(table)` + typed narrowing over per-column `select({...})` unless a join shape or perf need requires explicit columns.

## Migrations

Migrations are **generated by drizzle-kit**, never hand-written. Each schema domain has its own generate script (they differ by driver — `d1-http` for root, `durable-sqlite` for DO schemas):

```
npm -w db run build:db:root      # root D1
npm -w db run build:db:tenant    # tenant main + logs (durable-sqlite)
npm -w db run build:db:user      # user main
npm -w db run build:db           # all of the above
npm -w db run build              # types (tsc) + all migrations
```

Generated output (`migration.sql` + `snapshot.json` under `src/schemas/<domain>/<timestamp>_<name>/`) is Prettier-formatted by the `post*` scripts and committed. DO schemas also expose a `migrations.js` used at runtime inside the Durable Object (`_migrate()` in `BaseD0`).

Apply root D1 migrations remotely: `npm -w db run publish:dev` / `npm -w db run publish:prod`.
